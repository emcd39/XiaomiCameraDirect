## A03 — CS2 peer validace a dostupnost živého měření, 2026-11-12

- `WriteUntil` již omezoval odpovědi na IP zvoleného cíle a při validní handshake odpovědi ukládal zdrojový port; další požadavek proto šel na dohodnutý ephemeral port. `udpConn.Read` ale dříve povoloval libovolnou zdrojovou IP pro každý datagram o délce alespoň 8 bajtů. Tato výjimka byla odstraněna: handshake i čtení nyní používají porovnání `net.IP.Equal`, které zohledňuje 4bajtové IPv4 a 16bajtové IPv4-mapped/IPv6 formy.
- `newUDPConn` nově předává explicitní cílový port do resolveru a volí `udp4`/`udp6` socket podle vyřešené cílové adresy; testy tak pokrývají také rodinu socketu místo neurčitého dual-stack chování Windows.
- Regrese: `TestUDPReadRejectsForeignIPv4DatagramLargerThanEightBytes` (cizí IPv4 datagram se stejnou délkou jako běžná data je přeskočen); `TestSamePeerIPHandlesIPv4AndIPv6Representations` (4/16bajtové IPv4, IPv4-mapped, komprimované i rozvinuté IPv6 a odlišné IP); `TestNewUDPConnUsesExplicitPeerPortAndAddressFamily`; `TestHandshakeAcceptsLegitimateCameraPortChange` (validní stejná IP, nový port pro punch i READY). Cílený příkaz `go test -race ./internal/xiaomi/protocol/miss/cs2 -run '<four A03 regressions>' -count=1` prošel, log `.test-env/evidence/cs2-peer-race-20261112.log`; balíček `cs2` také prošel kompletní race sadou `go test -race ./...` (`1.392s`). `go vet ./...` také prošel.

### Dostupnost identity pro headless test

Kontrola místního hostu 2026-11-12 nenašla proces gateway/diagnostické konzole ani TCP listener na diagnostických portech `63983`, `8099`, `8123` a `8554`. V tabulce sousedů nebyl záznam pro `192.168.2.84` ani `192.168.2.184`; v tabulce tras nebyla konkrétní trasa `192.168.2.0/24`. Proto nebyl dostupný běžící lokální autorizovaný gateway endpoint/inventář, přes který by šlo provést headless read-only přiřazení. Nebyl použit token, zahájen nový cloudový login ani odeslán požadavek na gateway či kameru.

K pokračování identifikace je potřeba spustit již autorizovanou gateway se zpřístupněným lokálním inventářem a získat úplnou MAC adresu každé kamery. Teprve přesná položka inventáře může potvrdit vazbu IP ↔ MAC ↔ modelové ID ↔ firmware. Samotný prefix MAC, název C400/Mi 360 ani dostupnost adresy tuto vazbu nedokládají. Po potvrzení identity se video, PTZ a přímá lokální datová cesta musí ověřit samostatným živým důkazem pro každou kameru; současný záznam neprokazuje podporu žádné z těchto funkcí.

## M01 — explicitní profil C201, 2026-11-12

- Přidán `internal/xiaomi/profiles`: verze profilu, přesné model ID, regiony, přesné ověřené firmware, MISS vendor, aplikační a mediální protokol, codec, channel, quality, audio a rozdělení na baseline/firmware-ověřené features. Profily neobsahují DID, IP ani tajné údaje. Duplicitní model+region stejné specificity+firmware se odmítne; regionální profil a wildcard fallback mohou koexistovat. Pokud bez firmware nelze jednoznačně vybrat mezi více profily stejné specificity, resolver vrátí ambiguity.
- Resolver vyhodnocuje firmware a přípustný region společně: přesný region má přednost před `*` pro stejný firmware, ale přesná firmware shoda v `*` profilu se nezahodí jen proto, že dotaz přišel z konkrétního regionu. Wildcard výsledek má `RegionKnown=false`, včetně doslovného vstupu `region="*"`, takže neodemkne regionově ověřované features. Při chybějícím firmware se dál zvolí jednoznačný přesný regionální C201 profil jen pro baseline.

### A03 — offline policy core pro lokální média, 2026-11-12

- Přidán izolovaný balíček `internal/xiaomi/localmedia`. `Policy.Open` váže požadavek na DID, model, firmware (včetně explicitně prázdné neznámé hodnoty), IP, případný ověřený MAC a revizi inventáře. Cíl musí být číselná lokální unicast IP v explicitním CIDR; konfigurace je dvojice CIDR + rozhraní. Veřejná/loopback/multicast IP, hostname, chybějící nebo nejednoznačné pravidlo a route přes jiné rozhraní selžou uzavřeně.
- Fáze jsou: inventory snapshot → route/interface preflight → nový snapshot → `CloudPreparer` pro stejné DID → opětovný snapshot a route/interface check → `SessionOpener` dostane přesnou ověřenou IP, revizi a povinné rozhraní. Změna IP/revize před cloudem nevyvolá cloudovou operaci; změna během cloud přípravy nepokračuje k openeru. Cloud preparer a socket opener jsou oddělené, takže budoucí `offline_required` je nemůže omylem zaměnit.
- Fake-only regrese ověřují úspěšné otevření a pořadí volání, odmítnutí mimo CIDR / jiného rozhraní / veřejné IP / hostname před cloudem, stejné DID se změněnou IP a/nebo revizí, změnu během cloud přípravy, změnu trasy těsně před otevřením, nesoulad modelu/firmwaru/MAC a nejednoznačný allowlist. Testovací balíček nevytváří sockety ani požadavky na gateway/kameru.

### A03 — vynucení `local_media_required` v provideru, 2026-11-12

- Produkční `cameraSource.start` nyní při výslovném `XLG_XIAOMI_LOCAL_MEDIA_REQUIRED=true` volá policy před přípravou relace. Režim zůstává ve výchozím stavu vypnutý. Správce nastaví `XLG_XIAOMI_LOCAL_MEDIA_NETWORKS` ve tvaru `CIDR@interface`, více pravidel oddělí středníkem. Chybějící/neplatné pravidlo odmítne konfiguraci; podporováno je nejvýše 16 pravidel a 2048 znaků.
- Policy používá poslední úspěšný inventář provideru, pouze pokud je mladší než 30 sekund; každé obnovení zvýší revizi. Před cloudovým `MissVendor` ověří DID, model, firmware dostupný v inventáři (u C201 je neznámý/prázdný), IP, dostupnou MAC, explicitní CIDR a systémovou trasu. Po `MissVendor` znovu ověří inventář a trasu a po druhém route lookupu načte inventář ještě jednou. Změna IP/revize u stejného DID během této kontroly nedosáhne media openeru.
- `SystemRouteResolver` určí trasu připojeným UDP socketem bez odeslání datagramu a namapuje vybranou zdrojovou IP na právě jedno aktivní OS rozhraní. CS2 UDP handshake i vyjednaný TCP/UDP socket jsou připnuté k přesnému rozhraní (Linux `SO_BINDTODEVICE`, Windows `IP_UNICAST_IF`/`IPV6_UNICAST_IF`); jiné platformy selžou uzavřeně. Session se otevírá na přesné IP z ověřeného inventáře. Po handshaku provider zkontroluje peer IP, přičemž vyjednaná změna portu zůstává platná. Chyba nevede k relay ani k jiné cílové IP. Účet a MISS key material stále vyžadují cloud; `offline_required` zde implementované není.
- Při obnovení inventáře provider už znovu nepoužije zdroj se stejným DID, pokud se změnila IP nebo MAC; starý zdroj/session je ukončen a nová session musí projít novou revizí. Logy preflightu ukládají jen stabilní důvody odmítnutí, bez IP, tokenu a surových chyb.
- Provider regresní testy potvrzují jeden `MissVendor` a právě jeden media opener pro povolený cíl a předání přesné IP/rozhraní. Route mismatch před cloudem má nula `MissVendor` a nula otevření. Změna IP/revize stejného DID během druhého route lookupu má nula otevření. Další test pokrývá konfiguraci a nahrazení zdroje při změně endpointu. `localmedia` regresní testy navíc pokrývají IP-only, revision-only, současnou změnu, chyby identity/MAC/modelu/allowlistu a změnu během cloud přípravy.
- Ověření: cílený Windows `go test` nad `internal/xiaomi/localmedia`, `internal/xiaomi`, MISS a stream prošel; zahrnuje `TestProviderReplacesSourceWhenSameDIDGetsNewIP` i provider policy scénáře. Headless Linux `wslc build --progress plain --target go-race .` a `wslc build --progress plain --target go-vet .` prošly (`EXIT_CODE=0`); evidence: `.test-env/evidence/localmedia-required-final-go-race-20261112.log`. Celá Go race sada zahrnuje Linux loopback route + skutečné připnutí lokálního UDP socketu; žádný datagram na kameru/gateway se neodesílá. `git diff --check` také prošel.
- Fyzické ověření A03 se neprovedlo: není zde nové měření peeru/trasy C201 ani izolace WAN za běžící session, restartu, nové session či settings. `C201_VIDEO=UNVERIFIED`; C400 (`192.168.2.84`) a Mi 360 (`192.168.2.184`) stále čekají na přesnou identitu. Mock a loopback testy nejsou živým důkazem kamery.

#### A03 follow-up — pořadí inventářových výsledků, 2026-11-12

- Každé volání `cameraDevices()` přidělí pod `Provider.mu` rostoucí pořadové číslo ještě před rozhodnutím, zda čte cache nebo volá Xiaomi inventory. `publishCameras()` pod stejným mutexem zveřejní pouze výsledek, jehož číslo není starší než naposledy zveřejněný výsledek. Starší dokončený request použije kopii právě aktuálně zveřejněných `devices`, zachová jejich `sources`, revizi a čas; nemůže staré IP obnovit ani ji označit novou revizí.
- Deterministické regrese: `TestProviderDoesNotPublishDelayedCachedInventoryAfterRefresh` pozastaví cache snapshot mezi načtením a publikováním, zveřejní novou IP a poté zkusí zveřejnit odložený starý výsledek. `TestProviderOverlappingRefreshesCannotRestoreOldAddress` spustí dvě skutečná souběžná `Cameras()` volání nad falešným inventářem; druhé vrátí novou IP jako první a první starou IP až poté. Test ověří zachovanou revizi i čas, zavřený starý zdroj a následný lokální start na nové IP s novou revizí.
- `C:\Apps\go\bin\go.exe test ./internal/xiaomi -run 'TestProvider(DoesNotPublishDelayedCachedInventoryAfterRefresh|OverlappingRefreshesCannotRestoreOldAddress|ReplacesSourceWhenSameDIDGetsNewIP|LocalMediaPolicyPinsVerifiedTargetAndOpensOnce|LocalMediaPreflightAndStaleSecondRouteNeverOpenSession)' -count=1 -v` prošel na Windows.

## Why Windows was used; how the Linux gateway runs

Windows was used for historical diagnostics because the only available signed-in Xiaomi Viewer profile is stored under the Windows user account and its token is protected by DPAPI. `scripts/test-c201-ha.ps1` decrypts that token locally under the same user, places it in a private temporary environment file with restricted ACLs, passes it to the Linux gateway container, then deletes that file. The token is not written to evidence. DPAPI is test-harness plumbing; it is not part of the gateway or target Linux Home Assistant integration. A production Linux setup still needs its own secure account pairing or secret storage.

The gateway itself already builds and runs on Linux: [Dockerfile](../Dockerfile) compiles a static Go `xlg` binary and places it in an Alpine Linux runtime image. The physical pilot builds this image from the checkout and starts it beside a fresh Home Assistant container. This currently runs through WSLc NAT, so it verifies the Linux binary and HA integration but not a direct Linux-to-camera LAN route or deployment to the user's actual HA OS.

**Current physical status:** The direct Windows C201 pilot completes CS2 LAN search/punch, opens `cs2+tcp`, and receives H.265. The 2026-11-07 L2 run decoded 5 minutes (5,937 frames, 848×480) and three fresh RTSP connections each decoded five frames; the stream was sent to FFmpeg's `null` output, so its visual content was not inspected or saved. Startup produced HEVC missing-reference errors; the roughly three seconds recorded for reconnects is the whole five-frame attempt, not a measured time to first frame. L2 time/reconnect criteria are met. A short physical HA HLS attempt at 10:01 CEST stopped before HA startup because WSLc/WSL returned `E_ACCESSDENIED`; HA port 8123 was not listening, no `camera/stream` request was sent, and network rules were unchanged. Physical HA HLS, ten-minute HA playback/recovery, visual confirmation, and PTZ remain unverified. Current Xiaomi provider keeps PTZ unsupported and unwired. See [NEXT-TASK.md](NEXT-TASK.md) and [diagnostika/PLAN_C201.md](../diagnostika/PLAN_C201.md).
